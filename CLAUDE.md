## Architecture

This is a Next.js 16 App Router marketing site for "BeyondLab Academy" — a Thai tech-learning brand ("ห้องทดลองของคนที่อยากก้าวข้ามขีดจำกัด") run by two founders/tutors (พี่โม, พี่มิก). It's broader than pure tutoring: a C++ course (ZERO TO CODE), project consulting, and a shipped product (QuizFlow), with more services authored but not yet launched (IoT kit, LINE Bot). It's a hybrid site: a single-scroll landing page at `/` plus a couple of dedicated content routes.

- [src/app/layout.tsx](src/app/layout.tsx) is the shared shell for every route: it renders the fixed background, `Navbar`, and `Footer` around `{children}`, so new routes automatically get consistent nav/footer without re-importing them. It also loads the site's only font (IBM Plex Sans Thai) via `next/font/google`.
- [src/app/page.tsx](src/app/page.tsx) composes the homepage as a fixed sequence of section components: `Hero`, `AboutTutors` (`#about`), `BuildGrid` (`#courses` — the course listing/detail card), `ServicesSection` (`#services` — grid built from `visibleServices`), `ProjectShowcase` (`#projects` — portfolio teaser), `InteractiveTerminal` (decorative, no anchor), `Community` (`#contact` — contact channels), `FinalCta`. Adding a new homepage section means creating a component and inserting it into this list in the right scroll order. Note: `Roadmap.tsx` still exists in the components folder but is currently **not** imported into `page.tsx` — don't assume it renders without checking.
- [src/app/portfolio/page.tsx](src/app/portfolio/page.tsx) and [src/app/services/page.tsx](src/app/services/page.tsx) are standalone routes (not homepage sections) for the portfolio gallery and full service listing — content-heavy areas that don't fit a scroll section. Follow this pattern (a route under `src/app/<name>/page.tsx`) for future content-heavy areas; keep quick, low-content additions (e.g. more contact channels) as homepage sections instead.
- All section components live flat in [src/app/components/beyondlab/](src/app/components/beyondlab/) — there is no nesting by feature or type. New sections should follow this same flat placement.
- [src/app/components/beyondlab/data.ts](src/app/components/beyondlab/data.ts) centralizes copy/content as exported arrays/objects (e.g. `navItems`, `tutors`, `courses`, `roadmapItems`, `services`, `contactChannels`, `portfolioCategories`, `pastCourses`) and shares their TypeScript shapes (`ServiceItem`, `ContactChannel`, `CourseItem`). Components/pages import from here rather than hardcoding content inline — follow this pattern for any new static content, keeping components focused on markup/layout. `services` entries can be authored ahead of launch with `hidden: true` (e.g. the IoT kit and LINE Bot rows); `ServicesSection` and `/services` only render `visibleServices`, the filtered/exported list — flip `hidden` to `false` (or remove it) when a service is ready to show.
- [src/app/portfolio/[slug]/page.tsx](src/app/portfolio/[slug]/page.tsx) is a statically-generated (`generateStaticParams`) detail page for individual `pastCourses` entries, looked up by `slug`. Cards on the homepage teaser (`ProjectShowcase`) and the `/portfolio` list link to it once a `pastCourses`/`portfolioPreview` item has real content (an `href`/`slug`) — items still marked "เร็วๆ นี้" stay non-clickable. Follow this pattern for other portfolio categories (e.g. competition results) once they have real per-item content worth a detail page.
- [src/app/components/beyondlab/icons.tsx](src/app/components/beyondlab/icons.tsx) holds shared inline SVG icon components (e.g. `ArrowIcon`); `Logo.tsx` is a separate standalone component.
- Site copy is in Thai (`lang="th"` in the root layout). `Navbar`/`Footer` use `next/link` so links work from any route: in-page anchors are written as `/#section-id` (e.g. `/#courses`, `/#contact`) so they resolve correctly even when clicked from `/portfolio` or `/services`; homepage section components still carry the matching `id` attribute — see the list above for which id belongs to which section.
- Contact/community channels (Instagram, LINE, Discord) live in `data.ts` as `contactChannels` and render on the homepage `Community` section, the `Footer`, and `FloatingContact` (a site-wide floating button that prefers LINE, falling back to the first channel with an `href`); entries with `href: null` render as "เร็วๆ นี้" (coming soon) — fill in the real URL once available instead of adding new fields. Each channel's `logo` field points to a PNG in `public/logos/` (real brand logos, not hand-drawn icons) — rendered via `next/image`; add new channel logos there following the same `/logos/<name>.png` convention.
- Styling is Tailwind-only, applied via utility classes directly in JSX (no CSS modules, no styled-components). The body font is IBM Plex Sans Thai (covers Latin and Thai in one family), self-hosted via `next/font/google` in [src/app/layout.tsx](src/app/layout.tsx) as the `--font-ibm-plex-sans-thai` CSS variable, consumed by `body { font-family: ... }` in [src/app/globals.css](src/app/globals.css). [src/app/opengraph-image.tsx](src/app/opengraph-image.tsx) separately fetches the same IBM Plex Sans Thai weight from Google Fonts at generation time (the `next/font` variable isn't available inside the `next/og` renderer) so Thai text renders correctly there too — keep them in sync if the body font ever changes. `globals.css` otherwise holds only global concerns: a few reusable utility classes (`.aurora-text`, `.animate-float`) and keyframe animations. Prefer Tailwind utilities in components; add to `globals.css` only for things Tailwind can't express.
- Path alias `@/*` maps to `./src/*` (see [tsconfig.json](tsconfig.json)).
- No client-side state management, routing library, or data-fetching layer is present — components are static/presentational.
